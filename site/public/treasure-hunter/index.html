The product

One hunt, in five lots

Screens from the working app, run locally against live eBay listings on October 9, 2026. Each is cropped to the part described; tap one to see the full screen.

Lot 1 · The target

Say it in plain words

"Anything signed by Bobby Jones." A low-cost model turns the sentence into filters you can see and edit: the subject, who must have signed it, aliases, and words to rule out. It knows golfer Bobby Jones is not the basketball player of the same name.

Lot 2 · The hunt

A deal board, not a search page

Code screens every listing first: wrong signer, reproductions, other sports. Survivors go to the model in batches, and every verdict must quote the listing or it's discarded. Live auction-house lots are screened in the same pass and flagged as a second hunting ground.

Lot 3 · The value card

The price story, done in code

Cost to acquire, wholesale from approved auction comps, a sell value that always names its source, eBay fees, max to pay and margin. Here, a $331 buy against a $556.74 ceiling. With fewer than three comps the card says "thin" or "insufficient" instead of guessing.

Lot 4 · The receipts

Every number opens its records

Click any figure and the sales behind it appear: hammer, buyer's premium, shipping (actual or estimated) and a link to the original lot page. A test feeds the app a fake model that "states" prices and proves none of them reach a money field.

Lot 5 · The researcher

The one agent, on a short leash

On demand it pulls a listing's claims, chooses its own searches through the auction archive, and files a report. Its test case: a lot claiming feather balls were made "until 1950." It flagged the conflict and cited an archived gutty ball from c.1865. A verdict stands only if code finds its quote in a record the agent actually fetched.

Engineering decisions

Rules the code enforces

No price from a model

Models extract, compare and cite. Arithmetic lives in one module with exact decimals, and any model-stated number on a money field fails the tests.

Quote it or drop it

Attributes, screening verdicts, comp reasons and research findings all carry the exact words they came from. Code looks for those words and discards whatever it can't find.

One agent, bounded

Only the researcher decides its own steps, because only that job needs open-ended lookups. It has a step cap and a cost cap and must cite fetched sources.

Spend is metered

Every call is costed from its token usage and logged. A counter in the app shows each run's tokens and dollars against the monthly cap.

Polite data access

Both auction houses block scripts, so nothing crawls. Pages were viewed in a browser at human pace, saved with checksums, and never re-read once a sale closed.

Marketplace rules in code

eBay data follows the API license: a daily call cap, listings shown with their age after six hours, no seller data or images stored, and a 30-day purge.

Measured, not claimed

How good are the prices?

70%of actual sale prices fell inside the comp range (217 of 311 archive lots) 71price ranges recorded for live auction lots before they close on October 18, scored after

How the backtest works. Each past lot is priced only from sales dated before it, then compared with what it actually made. This run uses code-picked comps alone, with no model and no human approval: the floor, not the product.

The harder numbers. 43% of lots had a comp median within 2× of the actual price, and only 26% of the 1,219 archive lots had three or more earlier comps to price from. Thin data is the main limit, which is why the card says "thin" or "insufficient" instead of guessing.

One-off memorabilia prices vary widely, so the honest claim is a ballpark. The scorecard is built to show whether model-proposed, human-approved comps tighten it.
